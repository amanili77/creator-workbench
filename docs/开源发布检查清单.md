# 开源发布检查清单

这份清单用于把本项目发布到 GitHub 前做最后确认。

## 发布前

- [ ] `git status --ignored` 确认 `用户数据/`、`runtime/`、`output/` 均为忽略状态。
- [ ] 搜索真实姓名、昵称、邮箱、手机号、家庭/公司地址和个人绝对路径。
- [ ] 搜索 API Key、Cookie、Token、密码、私钥、数据库和浏览器 Profile。
- [ ] 确认没有通过 `git add -f` 强制加入敏感文件。
- [ ] 确认 `config.example.json` 只含占位值。
- [ ] 确认助手图片、空间背景、字体和其他素材拥有公开再分发权。
- [ ] 若素材版权不明确，先替换或移出仓库，再创建公开仓库。
- [ ] 在一个全新的临时数据目录中启动并完成基本功能检查。
- [ ] 阅读 `LICENSE`，确认 MIT 许可证符合发布意图。

## 推荐命令

```powershell
git status --short --ignored
git ls-files
git diff --cached
```

首次发布可使用：

```powershell
git init
git add .
git commit -m "Initial open-source release"
git branch -M main
git remote add origin https://github.com/你的账号/creator-workbench.git
git push -u origin main
```

如果任何敏感文件曾经进入 Git 历史，仅删除当前文件不够。不要先推送；应轮换相关凭据，并使用 `git filter-repo` 等工具清理整个历史后重新检查。

## GitHub 仓库建议

- 仓库名：`creator-workbench`
- 简介：`A local-first creator workspace for ideas, topics, scripts, planning and AI-assisted workflows.`
- Topics：`creator-tools`、`local-first`、`flask`、`productivity`、`ai`
- 默认分支：`main`
- 开启 Dependabot alerts 和 secret scanning（仓库类型支持时）

## 发布后

- [ ] 从 GitHub 下载 ZIP，在新目录中按 README 完成安装。
- [ ] 检查仓库网页中没有 `用户数据/`、Cookie、数据库或真实配置。
- [ ] 创建首个版本标签，并在发布说明中列出平台限制和隐私边界。
