# AGENTS.md — 给 AI 的操作契约

> 这是本知识库的规范。任何 AI 会话在这个目录下工作时，**先完整读完本文件**，再动手。
> 本文件由人和 AI 共同演进：发现规则不适用时，直接改这里，并在 `维基/日志.md` 记一条。

---

## 一、这是什么

基于 Karpathy 的 LLM Wiki 模式：不是 RAG（每次提问从原文重新检索），而是**增量编译**。

每加入一份原始素材，AI 读它、提炼它、把它织进已有的维基页——更新实体、修订概念、标注矛盾。知识编译一次、持续保鲜，而不是每次提问重新推导。

**三层，就这三层：**

| 层 | 目录 | 谁写 | 谁读 | 能不能改 |
|---|---|---|---|---|
| 原始素材层 | `原始素材/` | 使用者 + 工作台程序 + 采集插件 | AI | **AI 永不修改、永不删除、永不移动** |
| 维基层 | `维基/` | AI | 使用者 | AI 全权增删改 |
| 规范层 | `规范/` + 本文件 | 人和 AI 共同演进 | AI | 改了要记日志 |

**没有别的了。** 不需要额外脚本、不需要索引数据库。「哪些素材收录过了」这件事，**git 就是账本**（见第五节）。

> **`原始素材/工作笔记/` 的定位**：使用者的手写笔记属于素材源，要收录。
> 其中 `01-创作中心/` 是工作台数据库的自动镜像（见第十二节）——收录时照常建页，但**不要反向修改这些文件**，改了会被下一次同步覆盖。
> **不建页的只有**：纯导航与清单类（`00-*` 开头的总览、`*索引`、`参考资料/`、`照片.md`、`历史个人信息.md`）。

---

## 二、三条铁律（违反即停止工作）

1. **原始素材层只读。** AI 对 `原始素材/` 只能读。不改名、不删、不整理、不"顺手优化格式"。
2. **不编造。** 维基页里每一条事实，都要能追到某份原始素材。查不到就写「知识库里没有」，不许用常识填充。
3. **日志只追加。** `维基/日志.md` 只能往后加，不许删改已有条目。

## 四、三种工作模式（一次会话只做一种）

### 模式 A：收录（ingest）
触发：「收录新素材」「更新知识库」「我加了新东西」

### 模式 B：查询（query）
触发：问句。「XX 是什么」「对比 A 和 B」「素材里关于 XX 都说了什么」

### 模式 C：体检（lint）
触发：「体检」「检查一下知识库」「有没有矛盾/孤儿页」

**判断不准就问。** 不要自作主张把查询干成收录。

---

## 五、收录流程（逐步执行，别跳步）

### 第 1 步：用 git 找出新素材 —— 必做，不可跳过

```bash
git status --short 原始素材/
```

输出三种状态：

| 标记 | 含义 | 怎么办 |
|---|---|---|
| `?? 路径` | **新增，没收录过** | 这就是要处理的 |
| ` M 路径` | 收录过但被改了 | ⚠️ 原始层不该改，先跟使用者确认再重收录 |
| ` D 路径` | 收录过但被删了 | ⚠️ 维基里有悬空引用，体检时处理 |

**只看 `维基/日志.md` 判断收没收过是不够的** —— 每次都要跑这条命令。

### 第 2 步：逐条处理，先汇报再写入

对每份新增素材，**先输出一段摘要 + 你打算动哪些页面**，等使用者确认后再写文件。

批量不超过 5 份；超过就分批。（理由：Karpathy 本人也建议一篇一篇 ingest 并保持人在环内。全自动批量写入会让维基质量失控。）

### 第 3 步：写维基页

- 素材摘要页 → `维基/素材摘要/<标题>.md`
- 抽出的实体 → `维基/实体/<名称>.md`
- 抽出的概念 → `维基/概念/<名称>.md`
- **开新页门槛**：一个实体/概念要有 **≥3 份不同素材**提到，才单独开页；否则写进已有页面的「提及」小节。
- 一份素材正常会碰到 5～15 个页面。

### 第 4 步：更新索引与总览

- `维基/索引.md`：加条目（链接 + 一句话摘要 + 日期 + 来源数）
- `维基/总览.md`：只有当新素材**改变了整体判断**时才改，不要每次都动

### 第 5 步：记日志

`维基/日志.md` 追加一行，格式固定：

```
## [YYYY-MM-DD] ingest | 素材标题
- 新增页面：…
- 更新页面：…
- 存疑：…
```

### 第 6 步：提交 —— 这一步等于「标记已收录」

```bash
git add -A && git commit -m "收录：<素材标题>"
```

不提交，下次 `git status` 还会把它列为新素材。

## 六、查询流程

1. 先查 `维基/索引.md` 和 `维基/总览.md`，判断有没有相关内容
2. 有 → 读对应维基页，需要时再回溯到 `原始素材/` 原文核对
3. 没有 → 直接说「知识库里没有」，不要用常识填充
4. 答案值得沉淀 → 写进 `维基/问答/<问题>.md`，并在 `维基/索引.md` 加一条

---

## 七、体检流程

- **孤儿页**：没有任何页面链接到它的维基页
- **悬空链接**：`[[双链]]` 指向不存在的页面
- **矛盾**：同一事实在不同页面说法不一致 → 标出并回溯原文
- **欠账**：`原始素材/` 里有文件但 `维基/` 里没有对应摘要页
- **过时**：被新素材推翻但没修订的旧结论

体检结果写成一份清单，逐条跟使用者确认后再改。

## 八、页面格式

维基页统一用 frontmatter + 固定小节：

```markdown
---
类型: 概念
来源数: 3
更新: YYYY-MM-DD
---

# 标题

## 核心内容

## 关键论断
> 每条论断后面括号里标来源，例如（来源：素材标题）

## 引发的疑问

## 相关
- [[另一个页面]]
```

## 九、语言与命名

- **全程中文。** 不写英文缩写。
- 页面内互链用 `[[标题]]`（Obsidian 双链语法）。
- 文件名不写日期（日期在 frontmatter 里），避免链接失效。
- 素材摘要页标题 = 素材核心命题，不要直接用文件名。

## 十、常见错误

| 错误 | 正确做法 |
|---|---|
| 直接改 `原始素材/` 里的文件 | 永远只读 |
| 跳过 `git status`，凭印象收录 | 每次会话先跑 |
| 收录完忘记 `git commit` | 下次还会列出来 |
| 一个概念只被提到 1 次就开页 | ≥3 份素材才开页 |
| 把答案只写在聊天里 | 沉淀到 `维基/问答/` |
| 用英文缩写 | 全程中文 |
| 往库里加脚本/工具目录 | 不要。知识库只装知识 |

## 十一、工作台镜像（单向，别手动改）

`原始素材/工作笔记/01-创作中心/` 是「创作者工作台」数据库的**只读镜像**，由工作台自动写入：

| 数据库 | 镜像到 | 文件名 |
|---|---|---|
| 选题 | `01-创作中心/01-选题库/{大号,小号}/` | `<标题>.md`，重名加 id 后缀 |
| 脚本 | `01-创作中心/02-脚本工作室/{大号,小号,广告}/` | 同上 |
| 日记 | `04-个人空间/02-日记/` | `<日期>.md` |

规则：

1. **数据库是唯一真源。** 在网页里增删改，文件实时跟着变；在 Obsidian 里直接改这些文件会被下一次保存覆盖。
2. **别手动动这些文件。** 改标题请改数据库里的标题，程序会自动重命名文件。
3. **删除不真删。** 数据库里删掉后，镜像文件移进 `01-创作中心/99-回收站/`，可手动取回。
4. **每个文件 frontmatter 里有 `id`**（对应数据库主键），程序靠它认人。**删掉 `id` 字段会让程序认不出这个文件。**
5. **脚本分三类：大号、小号、广告。** 广告是商单脚本，直接成稿、没有选题阶段——所以 `01-选题库/` 下**没有** `广告/` 目录。
6. **`AI 永不修改、永不删除` 的铁律依然有效** —— 这条铁律约束的是 AI，不是工作台程序。
